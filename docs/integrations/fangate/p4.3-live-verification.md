| `POST /products/{id}/media` (JSON attach) | `docs.fangate.app/api-reference/media.html` | Documented as `{"media_ids": [...]}` |
| `POST /products/{id}/media` (multipart) | `docs.fangate.app/guides/media-storage.html` | Supported as "legacy direct upload compatibility shim" |

### 3.2 Key Documentation Findings

1. **Media library is n:m** (`docs.fangate.app/api-reference/media.html`): Products link to library media via `POST /api/products/{product_id}/media` with `{"media_ids": [101, 102, 103]}`. This is the documented approach.

2. **Legacy multipart still works** (`docs.fangate.app/guides/media-storage.html`): "Legacy direct uploads can still create product media without the newer upload-session path." The backend has "compatibility logic to keep final-storage state aligned."

3. **Changelog confirms** (`docs.fangate.app/changelog.html`): "Regenerate OpenAPI after deploy if you rely on Swagger UI for the new /api/media operations." This means OpenAPI may lag behind the live backend.

4. **Webhooks CRUD** confirmed in "2026-06 outbound partner webhooks" changelog entry, but `POST /webhooks/test` is NOT listed.

5. **Product offers** are completely absent from all documentation — the word "offers" does not appear in any official Fangate source.

6. **Analytics, blur, epoch** are completely absent from all documentation.

## 6. Findings Summary

### 6.1 Confirmed Findings

1. **Media attach is PARTIAL/NON-CONFORMANT**: Official docs describe JSON `{"media_ids": [...]}` for n:m library linking; repository sends multipart/form-data with file bytes (legacy path). This is the most significant conformance finding. The legacy path IS supported per docs but is NOT the documented approach.

2. **4 offer endpoints have ZERO documentation**: The word "offers" does not appear in any official Fangate source (OpenAPI, docs.fangate.app, changelog). These endpoints are either undocumented internal features or were deprecated/removed.

3. **3 endpoints (blur, analytics, epoch) have ZERO documentation**: No evidence of existence in any official source.

4. **test_webhook not documented**: While webhook CRUD is documented, the `POST /webhooks/test` endpoint is not listed in the OpenAPI spec or docs.

5. **OpenAPI lag**: Changelog confirms "Regenerate OpenAPI after deploy" — the OpenAPI spec may lag behind the live backend.

6. **No callers in codebase**: All 8 unverified endpoints have implementations in `client.py` and `service.py` but NO callers in the repository. These are dead code paths.

### 6.2 Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|------------|
| Undocumented endpoints may not exist on live API | HIGH | Live probe required to confirm |
| Undocumented endpoints may be deprecated/removed | HIGH | Live probe required to confirm |
| Offer endpoints may create real commercial objects | HIGH | Use nonexistent IDs only |
| test_webhook may trigger real notifications | MEDIUM | Use nonexistent webhook ID |
| Media blur may be irreversible | MEDIUM | Use nonexistent media ID |
| Epoch trigger may be irreversible | MEDIUM | Use nonexistent product ID |
