## Offer API Verdict

**"Does Fangate actually expose the offer API used by this repository?"**

**NO.**

All five offer-related endpoints returned 404 with a real product ID:

- `POST /products/{id}/offers` → 404
- `POST /products/{id}/offers/{oid}/send` → 404
- `PATCH /products/{id}/offers/{oid}` → 404
- `DELETE /products/{id}/offers/{oid}` → 404
- `GET /products/{id}/offers` → 404

These routes do NOT exist on the live Fangate API at `https://fangate.info/api`. The repository's offer client methods (`create_product_offer`, `send_product_offer`, `update_product_offer`, `revoke_product_offer`) and service functions are dead code that will never succeed against the production API.

**Offer API existence**: **CONFIRMED-NOT-FOUND**

## Media Verdict

**"Is the repository's multipart media upload current, legacy-but-supported, or non-functional?"**

**The route exists but the repo uses the wrong approach.**

Live probe results for `POST /products/{id}/media`:
- 422 with `{"media_ids": [999999999]}` → "The selected media_ids.0 is invalid." (validates media_ids exist)
- 422 with `{}` → "The media ids field is required." (media_ids is required)
- 422 with `{"media_ids": []}` → "The media ids field is required." (media_ids cannot be empty)

The route **exists** and accepts JSON `{"media_ids": [...]}`. This matches the official documentation (`docs.fangate.app/api-reference/media.html`).

The repository's `upload_product_media()` method sends **multipart/form-data with file bytes**. This is a **different content type** than what the live API validates. The live API expects JSON with `media_ids`, not multipart file upload.

**Media attach classification**: **CONFIRMED-LIVE-NONCONFORMANT**
- Route: EXISTS
- Method: POST (correct)
- Body: JSON `{"media_ids": [...]}` (repo sends multipart)
- Legacy multipart support: UNDETERMINED (would need actual file upload to test)

## Remaining Unknowns

1. **Media multipart compatibility**: The repo's multipart upload approach was not tested (would require actual file upload). The docs mention "legacy direct uploads" are supported, but this could not be verified without uploading a real file.

2. **Offer endpoints with valid product/offer IDs**: All offer probes used nonexistent offer IDs (999999999). If real offer IDs existed, the behavior might differ. However, since the product itself exists and the routes return 404, the routes almost certainly don't exist.

3. **Analytics with valid data**: The analytics endpoint doesn't exist, so there's no data to validate against the parser.

4. **Webhook test with valid webhook ID**: The webhook test endpoint structure exists (405 on POST, 404 on PATCH/DELETE), but the actual webhook_id value could not be validated.

5. **Epoch with valid product**: The epoch endpoint doesn't exist, so there's no behavior to test.

6. **Rate limits**: Not tested (would require rapid sequential requests).

7. **Authentication edge cases**: All probes used valid Bearer token. Behavior with invalid/expired tokens was not tested.

The `upload_product_media()` method sends multipart/form-data. The live API validates JSON `{"media_ids": [...]}`. Two options:

1. **Migrate to JSON approach**: Change `upload_product_media()` to use JSON body with `media_ids` array. This matches the documented approach.
2. **Verify multipart compatibility**: Test whether the live API also accepts multipart (legacy path). This would require uploading a real file.

### Offer API (JUSTIFIED by evidence)

The offer API does not exist on the live Fangate API. If offer functionality is needed:
1. Contact Fangate to request offer API documentation
2. Or remove all offer-related code from the repository

### Documentation Gap (JUSTIFIED by evidence)

Several routes returned 405 (method not allowed) which proves they exist, but they're not in the OpenAPI spec:
- `DELETE /api/products/{id}/media/blur` — exists, not documented
- `PATCH/DELETE /api/webhooks/test` — exists, not documented

These should be reported to the Fangate team for documentation.
